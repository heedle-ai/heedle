Every invariant below is guarded by a test or a CI step, and CI checks this page against the code on every push with `bash .github/invariants.sh`. Only the **Guarded by** column counts. Each test named there must exist in exactly one package and is run, and must not be skipped; each `ci:NAME` must be a step in `.github/workflows/ci.yml`. Every `TestLaw_`, `TestInv_` and `Fuzz` test must be listed.

| ID | Invariant | Guarded by | Came from |
|---|---|---|---|
| HEEDLE-1 | heedle reimplements nothing: every loom command is `loom/cli.Run` and `heedle ui` is `drawdown/app.Run`, unchanged | `TestInv_HeedleIsLoomAndDrawdown` | One binary (roadmap 5.1) |
| HEEDLE-2 | `heedle up` refuses before starting anything without Git or the Temporal CLI, when Temporal's ports are taken, or when a flag after `--` would override the store, address or listen address it sets; it starts `temporal server start-dev` on 127.0.0.1 with its database in the home directory, then the UI and worker with the home's store and any other flags after `--`; it stops Temporal once the UI stops, even when the UI fails | `TestInv_UpStartsTemporalThenTheUI` | heedle up (roadmap 5.2); review 21: another Temporal on the ports was silently used, and `-store` after `--` silently won |
| HEEDLE-3 | On macOS, `heedle up` creates and starts Podman's virtual machine if there is none, starts the default one (or the only one) if none is running, and leaves one running or starting alone; on Linux it never touches Podman machines | `TestInv_UpPreparesPodmanOnMacOnly` | heedle up (roadmap 5.2); review 21: a starting machine, and one with another name |
| HEEDLE-4 | `heedle up` works for real: against a real Temporal dev server, a program submitted in the UI runs and is recorded, `heedle run` and `heedle beliefs` work against the same Temporal and store, and stopping heedle stops everything, Temporal included | `ci:e2e` | heedle up (roadmap 5.2); review 21: Temporal's stop wasn't checked |
